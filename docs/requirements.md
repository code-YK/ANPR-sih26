# Requirements and Traceability Ledger

This file translates the official challenge material into testable implementation and submission requirements. It is the execution checklist and the evidence index for the final presentation.

Official sources are coded in [source-register.md](source-register.md). The status column must describe merged evidence on `main`.

## Status vocabulary

- `Not started` - no merged implementation or evidence.
- `In progress` - implementation exists but acceptance evidence is incomplete.
- `Blocked` - cannot proceed without an external input or unresolved decision.
- `Ready for review` - acceptance evidence exists and awaits teammate review.
- `Done` - reviewed evidence satisfies the stated acceptance check.
- `N/A` - deliberately excluded with an accepted ADR and official compliance justification.

## Priority vocabulary

- `Mandatory` - required by official material or necessary to demonstrate it.
- `Conditional` - required only if the team selects that official model.
- `Selected` - required by the team's accepted architecture.
- `Bonus` - useful only after mandatory requirements work.
- `Administrative` - eligibility, dates, access, or submission operations.

```text
Test: tests/path/test_file.py::test_name
Demo: artifacts/public/checkpoint-c4/README.md
Docs: docs/architecture.md#section
PR: #123
```

Evidence must be reproducible and must not contain credentials, private feed URLs, personal data, or unauthorised footage.
